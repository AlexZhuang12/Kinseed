# Kinseed contributor instructions

Use synthetic individuals and separate private runtime data. Never change existing identities, birth records, memories, histories, permissions or life authorizations for a test. Do not modify original governance or declare Freeze.

The project uses AI-executed self-acceptance with honest disclosure of unperformed independent human, native-language and second-physical-machine checks. Keep failed/blocked historical results and source hashes; do not repair model answers or memories in the harness. See docs/AI_ACCEPTANCE_POLICY.md, ACCEPTANCE_SCOPE.md and OPEN_SOURCE_ENGINEERING_PLAN.md (revision7).

Run npm test, npm run ui:check, npm run test:ui and npm run release:check. Hosted CI/default tests use no real model accounts. Provider tests are explicit opt-in and may consume capacity. Preserve Chromium sandboxing and production safety boundaries.

Keep .private, local configuration, credentials, identities, memory, work, raw histories and private evidence out of commits and source exports. Export with scripts/export-source.mjs; package-lock and third-party notices must be included. Raw logs and screenshots are not public acceptance reports. Public artifacts must use synthetic content and be reviewed.

GitHub publication and capability changes require explicit Owner authorization; release governance permission is not life authorization. Use a separate clean source repository, never a private operational project or its Git history. Update guides, supported combinations, acceptance records and release notes with each change. Do not fabricate active support/security channels or untested model qualification.
