# 本地大腦三段式生活接頭（獨立候選）

這不是模型訓練或 LoRA。沿用同一模型、權重與受控 MCP，改變每次交辦的工作範圍。原 native／schema 接頭保留，預設不改，開發環境也不自動啟用模型。

## 三段工作

1. 系統先以當輪真實租約讀取 get_context。模型選擇本輪行動清單，只列工具名稱，不填內容；可以選空清單。最多十四個行動，加上情境讀取與提交，仍不超過原十六次工具限制。
2. 每個行動只提供該工具的原始內容 Schema，模型逐項填寫。前一步實際回傳會交給下一步。系統只產生請求編號，所有文字、來源編號、檔名、問題及其他內容仍由模型決定，原 MCP 再驗證權限與格式。
3. 行動清單處理完後，系統另外請同一模型整理整份 memory／plan、實際結果與 continue／wait，再加上原讀取版本與獨立提交編號，經原 commit_cycle 原子提交。失敗不猜補或重送。

系統不要求一定寫筆記、不替模型選任務、不補入遺漏記憶，也不把模型文字當工具成功。空 memory 仍表示清除目前摘要；舊 B 事件保留。前一筆記成功而記憶提交失敗時，筆記仍是真實歷史，不能回滾抹去或自動重做。

## 情境與原文

每步保留完整 identity_material、當前全部記憶／計畫、授權、剩餘時間、Owner 對話、來源與閱讀入口。完整身份已提供時，省略另一份重複身份索引的正文、歷史出生快照及不必由模型填寫的控制器編號。身份未完整提供時，保留原索引及分頁入口；不擅自裁切原文。

原始 get_context 與實際呈現內容都記錄在私人依據，以便核對這是明示欄位投影，並非聲稱整個物件無損壓縮。system prompt 與資料分開，但不宣稱可以完全消除提示注入。

## 啟用與追查

只在工程程式建立 lifeRunner 時明確使用 `adapterOptions: {toolProtocol:'staged'}`。目前沒有控制台啟用入口，也沒有更改正式來源或正式模型。依據新增 brain.stage、brain.stage_selection、brain.stage_content、brain.stage_submission 與 brain.stage_context。

仍採用同一截止時間、最多十七次模型回覆、原上下文與輸出預算。模型／服務摘要變更、停止、過期、權限拒絕、未知收尾均沿原路徑處理。重複失敗參數或相同成功寫入會停止，不以新的請求編號繞過重送防護。

## 限制與回退

行動名稱先選定，後續參數可依前面結果產生；本版沒有失敗後無限制重新規劃。單一行動失敗仍須由模型據實整理結果，格式合法不代表敘述真實。完整工具清單、長身份、接近容量上限的記憶及長期自主生活須另行驗證。

回退前先確認本候選沒有執行中的工作，移除 staged 選項，回到 native／schema；本次未遷移資料結構。不可用舊資料庫覆蓋歷史，不操作其他環境的模型服務，也不能以重啟推定生活授權。真實結果及失敗證據見本次工程交付報告。
