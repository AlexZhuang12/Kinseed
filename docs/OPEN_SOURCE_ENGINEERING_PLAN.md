## 剩餘順序

1. Owner指定D04：GitHub帳號或組織、庫名、公開方式及遠端操作授權。未授權前不建立Git／GitHub庫、不推送。
2. 從最終乾淨匯出建立獨立來源歷史，補正式庫網址；不能從含私人資料的原工程直接上傳。
3. 在授權範圍內設定Issues、私人漏洞通報及唯讀最小權限CI；核對通報入口、實際跑遠端Windows測試，失敗先修正重驗。
4. 發布前重新查已知漏洞並核對發布檔案；若程式或設定有變，更改來源指紋並重驗受影響範圍。
5. 依Owner授權範圍建立版本標籤及Release、來源附件／SHA、公開驗收連結。不同意公開就停在本機或私人候選，不代為公開。
