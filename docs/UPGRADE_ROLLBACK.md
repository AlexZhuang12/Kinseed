# 更新、備份與回退

目前沒有自動升級器或資料庫遷移器。本流程只適用於相容設定第 1–3 版與資料庫第 12 版的 Windows 預覽來源更新，不適用於其他正式環境。

## 更新之前

1. 在本副本控制台停止個體並確認工作收尾，再用本副本停止入口關閉控制台。不能以關瀏覽器取代停止。
2. 關閉本副本所有設定視窗，避免同時保存。備份工具會拒絕 session、未收尾租約、worker、running 或 paused 資料。
3. 在此副本執行 `npm run backup`。結果顯示私人備份完整位置及 PASS；若失敗，不繼續更新。
4. 執行 `npm run backup:verify -- "備份完整位置"`。它會校驗來源、設定、資料 SHA256、SQLite 完整性、歷史鏈及記憶投影。

備份位於 `.private/maintenance/`，內含來源、目前資料目錄及已保存設定，屬私人資料，未加密。不是全機備份：不含其他資料目錄、共用模型、Codex 登入、CLI 安裝快取或瀏覽器 sessionStorage。manifest 是完整性基準，不是簽署認證。請另用自己安全的方式留存離機備份。

## 套用相容來源更新

1. 在旁邊解壓乾淨的新來源，先閱讀版本說明，確認明確支援目前資料及設定；資料格式不相容時停止，不能試開舊程式遷移。
2. 本版只允許停機人工更新來源。按新舊 manifest 對照程式檔；保留原 `.private/` 與 `config/development.local.json`，不得以新空資料覆蓋。不要合併其他人的 runtime。
3. 若鎖檔變更，按新來源執行 `npm ci --ignore-scripts --no-audit --no-fund`，並重做依賴審查。`node_modules` 不作跨版本備份。
4. 先執行 `npm run boundary:check`、`npm run release:check` 及 `npm test`。這些測試會在自己的 `.private` 建合成資料，不會驗收正式模型能力。
5. 開啟本副本，核對個體身份、出生、記憶版本、歷史、權限及時間。啟動控制器不代表恢復生活，需 Owner 重新明確操作。

## 更新失敗怎麼回退

先停止本副本、確認工作收尾，再備份失敗當下的最新資料。只還原相容的舊程式及鎖檔，依需要還原相容的設定備份；保留目前資料庫與追加歷史。若新版本已寫出舊版不支援的格式，不得強行回退，應用相容讀寫修補。

本工具刻意不提供「覆蓋還原資料庫」命令。災難復原應將已驗證備份放到另一個隔離副本核對，不覆蓋仍在使用的資料，也不把舊生活授權當作恢復許可。備份驗證 PASS 不表示任何版本都可讀，也不代表已在第二台電腦完成復原驗收。

## 1.3.0-preview.1 相容範圍

資料庫仍為12版；網路資料庫有獨立且嚴格核對的 network-layout-1，不是忽略未知schema。新版備份會拒絕未知表／欄位、損壞的網路audit鏈及未收尾上傳。

舊安裝缺省生活時區維持Asia/Taipei，新安裝才可選其他時區。已使用非台北時區的資料不可回退到忽略時區的舊控制器；必須保留本版時區相容程式，否則會改變生活與額度日期。不得刪除timezone欄位或改記憶來迎合回退。新四語只影響顯示與本機接續；原身份與歷史不翻譯。
