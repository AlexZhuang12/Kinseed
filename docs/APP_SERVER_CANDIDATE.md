# app-server 獨立候選接頭：第一階段

候選標識：`app-server-phase1-20261027.1`。基線為 1.15.0-local.1。這是獨立合成工程，並非已部署版本或正式接頭選項。exec 原入口保留，沒有自動切換或未知結果後的跨接頭補送。

## 重現

在這份獨立候選的 app 目錄，使用既有 Node 24 與鎖檔依賴執行：

```powershell
node scripts/acceptance-app-server.mjs
npm test
npm run ui:check
npm run test:ui
npm run release:check
```

第一個命令只執行 53 項合成接頭測試，將當次日誌、結果及比較保存於 `.private/app-server-acceptance/<隨機識別碼>/`；不接受真實服務開關，不下載、不呼叫模型或付費平台。其餘為候選完整回歸。請勿將測試目錄指向正式資料。

主要測試位於 `tests/app-server-candidate.test.mjs`。AS39 使用獨立本機 HTTP 模擬供應商及另一個 Node 程序，模擬供應商已接受、本機隨即被終止，重啟後透過原請求識別查回，並核對提交總數仍為一次。AS46 透過原 exec 受控 MCP 與候選動態工具各完成同一份合成工作。AS53 以兩個真正的測試程序競爭過期鎖，確認只有一個管理者取得提交權。

## 接法與權責

- `adapter.mjs` 按需啟動、同個體重用程序，每輪新建 ephemeral thread；不使用 resume/fork。切換個體前關閉自己的舊程序。閒置 30 秒或累積 8 個 thread 後回收／輪替，單次只保留一個主程序。
- `controller-scope.mjs` 將原 Kinseed 工具、參數驗證與 lease 授權綁定本輪；測試預設只提供 get_context/write_note/commit_cycle。身份、記憶、B、時段、額度、daily 仍由原 Kinseed 管理。預設提示是合成提示，尚未接正式大腦設定或正式 UI。
- `settlement.mjs` 使用程序內不可由模型偽造的證明，區分「本輪與工具已收尾」與「整個程序已退出」。原 exec 仍沿用退出確認；候選可以保留已閒置的程序。不能用模型輸出或公開布林欄位當作收尾證明。
- `journal.mjs` 在本機持久保存意圖、回應及工作狀態，逐筆雜湊鏈、fsync、單管理者鎖及過期鎖恢復互斥。毀損／不完整紀錄拒絕繼續提交。
- `background-jobs.mjs` 保存外部工作意圖、穩定請求鍵及遠端 job ID。接受收據先落盤，再回覆模型；後續輪次查同一工作。未知結果不重送。付費接頭必須提供原預算預留鉤子，測試以合成記帳驗證一次預留／結算。

## 失敗處理

| 情況 | 候選處理 |
|---|---|
| 工具授權撤回／輪次結束 | 立即撤銷本輪工具能力；拒絕晚到、跨 thread／turn／個體呼叫 |
| 同 call ID 重複、同請求再次交付 | 同參數回原收據；不同參數拒絕；不再執行 |
| 取消只有 interrupt 確認 | 尚不當作收尾；等待終止事件或自身程序退出 |
| 斷線／逾時／退出無法確認 | unknown／隔離該位置；不換 exec 重做、不取消未來 daily |
| 遠端接受但回應遺失 | 依請求鍵查回原 job；供應商無查詢能力時保持未知、人工核對 |
| 遠端仍執行 | 保存 job ID、next-query 時間；原授權時段內有界查詢，時段外排下一時段，不加開生活 |
| 接受後 B 通知失敗 | 保留已落盤 ID 並標記待同步，不能因此再提交 |
| 重啟發現舊程序仍活著／不能確認 | 阻止新提交；不殺不確定歸屬的 PID |
| ledger／最終收據寫入失敗 | 不報成功或假收尾，保留 unknown；不自動重送 |

輪次結束與外部長工作分開追蹤。工作追蹤介面提供有界 `pollDue`，不另設會自行授予生活權利的常駐排程。Owner 明確停止優先；其他失敗只限制相關資源，不能取消每日安排。

## exec 對照與界線

同一份兩輪合成工作：兩邊均保存 1 份筆記、提交 2 輪、原平台計帳 2 次、最後記憶相同、daily 保持開啟。exec 主程序啟動 2 次；候選啟動 1 次、建立兩個新 thread。這是機制對照，模型被腳本取代，不能當作真實模型品質或效能比較。

**速度、RAM、token 效率均未實測。** 減少主程序啟動次數不等於已證明更快或更省記憶體；常駐程序反而可能提高閒置 RAM，須實測。

實際既有 CLI 0.164.0-alpha.11.1 僅離線匯出 JSON Schema／help。本版 `thread/start` 使用命名 permissions，不能同送 sandbox；dynamic tool 需要 type=function，tool response 需要 contentItems/success。`protocol-shape.json` 保留受測結構與來源 SHA；完整匯出維持私人。官方參考：https://learn.chatgpt.com/docs/app-server 。動態工具仍屬版本敏感的實驗功能。

未完成真實模型／登入／命名 sandbox 生效／供應商動態工具行為驗證。真實 transport 預設關閉，需獨立限次授權，使用空白專用 CODEX_HOME；不複製正式 OAuth，也不能假設現有登入自動可用。沒有 Hedra／Gmail 實際付費接頭綁定，沒有新安裝、生成或寄信。

不能承諾普遍的 exactly-once：若遠端沒有請求冪等或查回功能、本機永久毀損或落盤失敗，結果仍可能未知；安全選擇是保留紀錄、不盲目再做。恢復互斥鎖若自身崩潰而殘留，需確認無管理者後人工處理，不能任意刪鎖。

記帳結算或中央 B 同步失敗時會保留 pending 證據，但本階段尚未接入正式中央補帳／通知重送服務；不能把工作 ID 保全說成所有供應商的記帳收尾均已完成。後續接入實際供應商前須補上依原 request key 的冪等補帳與人工核對入口。合成比較只使用測試產生的內容，不證明模型能寫出相同答案。

## 下一階段建議

值得進入受限真實資格驗證，尚不適合正式切換。另行取得 Owner 授權後，建議最多 6 次固定模型／low 的合成回合，測登入、原 sandbox、工具收尾與取消，再量主程序峰值／閒置 RAM、端到端速度及用量。外部付費生成 0 次、安裝 0 項；沒有授權前不執行，也不承諾固定金額或帳號可用額度。
