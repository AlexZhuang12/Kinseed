# 連線失敗與每日生活安排

本修正不變更大腦、身份、記憶、權限、生活時段或額度。新規則只區分「當次可安全結束的模型連線失敗」與「必須停止未來自動執行的風險」。

## Owner會看到的行為

已辨識的連線路由失敗、暫時斷線、容量不足或已確認本機收尾的逾時，仍須通過原有授權、身份、額度、程序及工具收尾檢查。沒有寫入／外部操作／提交嘗試時，最多依30、90、180秒進行三次控制器重試，不更換模型；CLI本身的重連與控制器重試不同。

若三次仍失敗、時間已不足或當次額度不足，本次活動結束。若Owner先前已開啟每日生活，保留下次既定時段；本時段不會無限重開、不延長截止、不退還已計輪數、不額外增加額度。下次時段仍重新核對身份、權限、授權、預檢與額度。

畫面會明示本次失敗與每日安排仍開啟，不把失敗顯示成健康完成。沒有每日授權的個體不會因本修正自動取得未來生活。

## 必須繼續阻擋的情況

- Owner停止／暫停、全域停止、控制器重啟、身份或設定變更，仍取消原每日安排。
- 未知錯誤、登入失效、帳號用量限制、資料完整性或收尾異常，不能當成已確認的暫時連線失敗。
- 已嘗試寫入筆記、外部動作或記憶提交，不能盲目重送整輪；原對帳及不重複執行規則保留。
- 尚未確認本機程序／工具結束時，保留租約與共同工作位置，不派送重複工作。

## 驗證範圍

R01–R10合成案例涵蓋錯誤分類、三次精確延遲、同時段恢復且只提交一次、失敗後跨日繼續、期限與額度不足、未知／登入／帳號額度、部分寫入、Owner停止及未確認收尾。與既有控制器、每日生活及逾時案例合計62項定向；完整624項Node回歸與147項四語合成UI檢查通過。以上有重疊，不相加當獨立案例數。

原始CLI事件另做唯讀分類重播，修正前unknown，修正後transient；不是重新呼叫模型或修寫正式歷史。本次故障由合成執行器明示注入，沒有刻意中斷正式網路，也不宣稱已定位外部路由事故的底層責任。

首次額度案例直接修改合成控制設定，被原出生排程雜湊保護阻擋；已改由原Owner停止、額度設定及恢復接口建立合成條件，保護未放寬，原失敗紀錄保留。

正式部署狀態以根目錄AGENTS與本次交付證據為準。不能因候選通過就自行重啟正式控制器或恢復其他個體。
