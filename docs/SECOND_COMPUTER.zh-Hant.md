# 在第二台Windows電腦安裝Kinseed

適用：重新安裝乾淨程式、建立和管理新的個體。這不是搬遷原有個體，也不是兩台共用同一份資料庫。

## 安裝前先確認

- 使用Windows x64；Node.js需要24.19.0以上的24系列版本，其他主版本目前不接受。安裝Node後重新開啟終端機。
- 安裝Chrome；保留Windows原有沙箱與安全機制。實際OS、安全元件、記憶體與磁碟仍需在該機檢查；型號本身不能證明相容。
- Codex雲端大腦不需要先下載Whisper、Ollama或大型本地模型。影音、本地轉錄及大型套件屬額外需求，依資源另行開啟。
- 一般安裝先從[固定版本下載指南](DOWNLOADS.md)取得最新已發布預覽及同版校驗資料。若要clone開發來源才需Git；main的Code ZIP不等於固定發行，可能含未發布更新。

## 兩種帳號方式共用的步驟

1. 選擇自己的本地目錄，例如`C:\Projects\Kinseed`，不要放在會持續同步資料庫的OneDrive或其他雲端同步資料夾。
2. 取得來源：

   ```powershell
   git clone https://github.com/AlexZhuang12/Kinseed.git C:\Projects\Kinseed
   cd C:\Projects\Kinseed
   ```

3. 執行資料夾內的「首次設定.cmd」。依導引安裝鎖定依賴、選語言與生活時區。
4. 大腦選「使用自己的Codex登入」。依導引準備專案支援的CLI版本並在這台電腦登入，確認畫面的帳號／工作區是要使用的那一個。只在Codex桌面程式登入，不能代替Kinseed導引的CLI連線檢查。
5. 準備工具、檢查並保存設定，啟動控制台，再按導引提供的連結進入。第一次啟動只建立自己的空白私人環境。
6. 建立新個體，填寫出生條件 → 預覽 → 提交及批准身份 → 設定生活時段、輪數及權限 → 檢查平台 → 親自確認出生。若要每天生活，再確認每日安排已開啟。
7. 第一輪先用少量輪數觀察，核對模型活動、工具結果及保存狀態。之後用這份副本的開啟／停止入口操作，不沿用另一台電腦的網址或控制連結。

目前公開來源的日常入口仍沿用「開啟開發控制台.cmd」等檔名；它們操作的是這份安裝自己的環境，與開發者私人的原始平台無關。

電腦、控制器及網路需在生活時段內保持運作；單純關閉瀏覽器不等於停止控制器。新工具不是安裝後自動開權限，外部帳號及材料同意仍需各自設定。

新安裝不繼承開發者現用的個體輪數、平台總額度、網路分配、工具權限或付費帳號連線；依新電腦與新個體需要另外核對設定。

## 方式一：另一台電腦，使用不同Codex帳號

在第4步登入該使用者自己的帳號。Kinseed程式相同，但個體、記憶、作品、權限、網路及活動上限由該安裝自行管理。Codex可用能力、額度與工作區政策依該帳號而定；不同帳號不應直接當成兩份相同或無限制的資源，企業工作區也可能有共用限制。

不要複製其他人的Codex憑證、Owner控制連結、私人資料庫或第三方OAuth。需要Hedra或Gmail等功能時，使用自己明確授權的連線；Kinseed開源授權不附帶付費帳號或點數。

## 方式二：同一位Owner的第二台電腦，使用同一Codex帳號

安裝步驟相同，但在第二台重新完成自己的登入。建議兩台各自登入，不以複製憑證檔代替登入。

| 項目 | 同帳號兩台的結果 |
|---|---|
| 程式版本 | 可各自clone相同提交；Git更新程式，不搬個體資料 |
| 個體、記憶與歷史 | 各自在自己的私人資料夾，不因同帳號自動合併 |
| Kinseed活動／網路上限 | 各自計算；沒有跨機總額協調器 |
| Codex使用額度與服務容量 | 屬同一帳號／工作區，兩台活動會共同消耗可用資源 |
| 工具帳號與登入 | 每台另行配置；若兩台接同一付費工具帳號，該工具點數也可能共用 |
| Owner控制台 | 各機本機服務，`127.0.0.1`代表當下這台，不是另一台 |
| 原有個體 | 不會自動出現在第二台；本指南建立的是新的個體 |

兩台各設150輪不代表帳號多出300輪服務容量；輪數也不是固定Token成本。長上下文、諮詢、報告、工具委派與Owner自己的Codex工程都會影響實際用量。先用較小輪數並錯開高負載時段，觀察帳號用量，再決定上限；不是必須錯開，也不保證可同時無限制工作。

若兩台連同一Hedra或其他付費帳號，平台點數、各安裝的保留額與記帳也不能當作已跨機協調；各自的本機限制不會自動形成一個共同總上限。尚未建立跨機協調前，由Owner安排使用範圍並核對供應商餘額。

開發用途可分成`C:\Projects\Kinseed`正常使用副本，以及`C:\Projects\Kinseed-dev`工程副本。工程使用合成個體，不把正在生活的私人環境拿來跑測試。更新兩台時各自確認工作收尾、備份，再更新來源；不以舊資料覆蓋新歷史。

Codex登入與GitHub開發權限是兩件事。下載公開程式不必登入GitHub；需要提交程式修改時才另外使用有權限的GitHub帳號與分支。使用相同Codex帳號不會自動授予GitHub寫入權。

目前沒有跨電腦同步同一個體或多人管理同一資料庫的完整驗收方案。若未來要移動既有個體，應另作單一活動端、資料完整性、版本與權限遷移方案，不能直接複製後讓兩邊同時繼續生活。

## 第二台電腦的建議

先以Codex雲端大腦、少量輪數及基本工具完成首次驗收。實際RAM、剩餘磁碟、Windows版本及背景負載尚未量測，不承諾該電腦已通過相容性驗證；也不必為了開始使用就載入本地Whisper或生成模型。需要本地影音或音訊時再逐項量測。

## 官方帳號資料

登入與憑證方式見[OpenAI Authentication](https://learn.chatgpt.com/docs/auth)。Codex依方案、任務及模型消耗額度，見[官方使用限制](https://learn.chatgpt.com/docs/pricing)。同一帳號增加電腦不會增加方案配額；本專案沒有額外的Codex配額管理權。
